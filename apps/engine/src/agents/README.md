# Hosted agents

This directory contains the hosted-agent catalog, protocol adapters, model discovery, conversation history, and handoff services.

Use `/model` in Jolo or `jolo agent list` to inspect configured agents. Hosted CLIs must already be installed and authenticated separately. User JSON manifests belong under `agents/` in the profile data directory; `catalog.js` reads them at engine startup and `manifests.js` defines the built-in defaults.

Hosted programs run with the local user's privileges. Jolo mediates the operations exposed by their transports; it does not sandbox arbitrary programs at the operating-system level. See the [security policy](../../../../SECURITY.md) and [CLI guide](../../../cli/README.md).

Ask in chat to use the inline browser, for example: “Open Google in the inline browser and search for iPhone 13 Pro Max.” The agent calls `browser_open` to open or reveal the workspace's **Browser** pane, then navigates and interacts with it. No manual Browser button click is needed. Native Jolo and hosted Codex, Claude Code, and ACP agents can list tabs, navigate, inspect accessibility snapshots, click, hover, type, fill or clear fields, select native options, press keys, scroll, go back/forward, reload, inspect network metadata, and capture screenshots. The workspace must be open in Jolo desktop; external Chrome/Edge windows are not controlled by this integration.

Hosted transports receive the `jolo_browser` stdio MCP server when the run's workspace has an attached browser or a desktop pane that can open one, independently of the search index. Availability is checked for each new run, including resumed conversations; opening the desktop after a hosted run starts makes browser tools available on the next run. Its credential is limited to `browser.call` in the current run's workspace and is revoked when the run ends. Calls pass through Jolo's existing permissions, invocation records, deadlines, and browser broker. Screenshot results include MCP image content for the agent plus a stored artifact for Jolo's transcript. Raw CDP and arbitrary page JavaScript are not exposed. A page's content is data, not agent instructions.

Every chat transport receives Jolo's browser instructions on first and resumed turns: use the dedicated browser tools, never computer use or an external `iab` browser. Desktop run admission waits for its pane registration. Codex's extra approval for Jolo's own scoped MCP bridge is accepted for that call so the operation reaches Jolo's dispatcher; external-server questions and forms remain unaccepted.

Chat opens share the same workspace browse grant as the Browser button, without a separate consent dialog; see the [inline browser security policy](../../../../SECURITY.md#inline-browser-control). An agent cannot replace another workspace's open browser. It receives a busy error until the user closes or explicitly switches that browser.

The host serializes operations per tab and expires element references after navigation. Use the refs returned by `browser_snapshot`; use `tabId` from `browser_tabs` when several tabs are attached. Closing the pane or cancelling the run stops pending browser input. Run `bun run desktop:smoke --browser-chat` to verify that chat opens a closed browser pane and controls its page, or `bun run desktop:browser-smoke` to check the individual controls against local Chromium pages. The hosted MCP path is covered by the integration tests. For an explicit live-agent check using its installed CLI and existing login, run `bun run desktop:smoke --real-browser-agent codex` (or `claude` / `grok`); this uses the agent's account against a disposable local page and checks both first and resumed turns.
